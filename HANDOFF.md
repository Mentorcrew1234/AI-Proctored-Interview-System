## `static/exam/` — the pre-built frontend

The zip includes the **already-built** Vite output in `src/main/resources/static/exam/`.
This means you can run the app immediately without building the frontend first.
If you change frontend code, rebuild with `cd frontend && npm install && npm run build`.

## How to run locally (quickest path)

### 1. Set up MySQL

```sql
-- Connect to MySQL and create the schema (if it doesn't exist)
CREATE DATABASE IF NOT EXISTS proctor_interview;
```

### 2. Configure secrets

Edit `config/application.yml` — update the DB password to match your MySQL root password:

```yaml
spring:
  datasource:
    password: YOUR_MYSQL_ROOT_PASSWORD
```

The Gemini API key and SMTP credentials are already filled in. Change them if needed.

### 3. Build frontend (only needed once, or after frontend changes)

```bash
cd frontend
npm install
npm run build
cd ..
```

> **Or skip this step** — the zip already includes the built frontend in `static/exam/`.

### 4. Start the application

**Windows:**
```cmd
mvnw.cmd spring-boot:run
```

**Linux/Mac:**
```bash
chmod +x mvnw
./mvnw spring-boot:run
```

**Or use the convenience script (Windows):**
```cmd
start.bat
```

App starts at **http://localhost:8080**.

### 5. Sign in

| Email | Password | Role |

| `recruiter@demo.local` | `Recruiter@123` | RECRUITER |

## How to deploy on a server (AWS EC2 / any VPS)

### Option A: Docker (recommended for AWS)

```bash
# 1. Copy docker/.env.example to docker/.env and fill in real values
cp docker/.env.example docker/.env

# 2. Edit docker/.env:
#    DB_PASSWORD=<strong password>
#    JWT_SECRET=<at least 32 random characters>
#    GEMINI_API_KEY=<your key>         (optional — leave blank for offline mode)
#    INTERVIEW_AI_MODE=GEMINI          (or MOCK for offline)

# 3. Build and start (from repo root)
docker compose --env-file docker/.env -f docker/docker-compose.yml up --build -d

# App is at http://<server-ip>:8080
```

The Docker Compose stack runs its own MySQL — no external DB setup needed.

### Option B: Bare metal (systemd)

Full step-by-step is in `docs/system/deployment/DEPLOYMENT.md` and
`docs/system/deployment/VPS-SETUP-WALKTHROUGH.md`. Short version:

```bash
# 1. Install Java 25, MySQL 8, Node 24 on the server
# 2. Create the database
mysql -u root -p -e "CREATE DATABASE proctor_interview;"

# 3. Build the JAR
cd frontend && npm install && npm run build && cd ..
./mvnw clean package -DskipTests

# 4. Run it
java -jar target/proctor-interview-*.jar

# Or set up systemd — see DEPLOYMENT.md for the unit file
```

### HTTPS (required for camera access)

Browsers require HTTPS for `getUserMedia` (camera/microphone). `localhost` is
exempted, but any real deployment needs TLS. Recommended: nginx reverse proxy
with Let's Encrypt. See `DEPLOYMENT.md` § nginx + certbot.

## Key configuration (environment variables)

All configurable via env vars or `config/application.yml`:

| Variable | Default | Purpose |
|---|---|---|
| `DB_HOST` | `localhost` | MySQL host |
| `DB_PORT` | `3360` | MySQL port |
| `DB_NAME` | `proctor_interview` | Database name |
| `DB_USER` | `root` | Database user |
| `DB_PASSWORD` | *(blank)* | Database password |
| `JWT_SECRET` | dev default | JWT signing key (32+ chars) |
| `INTERVIEW_MODE` | `NORMAL` | `NORMAL` or `DEMO` (presentation overlay) |
| `INTERVIEW_AI_MODE` | `MOCK` | `MOCK` (offline) or `GEMINI` (live AI) |
| `INTERVIEW_QUESTION_MODE` | `FIXED` | `FIXED` or `ADAPTIVE` |
| `GEMINI_API_KEY` | *(blank)* | Google AI Studio key |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` | Which Gemini model to call |
| `MAIL_ENABLED` | `false` | Enable invitation emails |
| `MAIL_USERNAME` | *(blank)* | Gmail address |
| `MAIL_PASSWORD` | *(blank)* | Gmail app password (16 chars) |
